## 1. Paper targets

**Paper 1: the dataset.** Working claim: *first openly documented, expert-reviewed synthetic IEP benchmark with machine-checkable ground truth*. Contributions: (a) spec-first generation where code fixes all facts and pagination and an LLM writes only narrative prose, making annotations true by construction; (b) real-PDF-through-real-OCR realism with paired clean/degraded variants; (c) closed-world, provably fake identity design; (d) community-critique-before-build methodology (public RFC); (e) dataset-of-the-dataset evaluation: practitioner realism review, structural comparison to public samples, pipeline compatibility, planted-PII recall. Candidate venues: NeurIPS Datasets & Benchmarks track, ACL/EMNLP resource track, LREC, AIED, EDM; FAccT if the participatory/ethics angle leads.

**Paper 2: evaluating such systems.** Working claim: *an evaluation framework for parent-facing IEP AI (extraction, plain-language summarization, translation) under FERPA constraints*, with first measured results on a production pipeline. Contributions: (a) task decomposition + metrics per stage (faithfulness, per-field extraction F1, GEMBA-MQM-style translation QE with per-language human calibration, readability, redaction recall); (b) privacy-constrained eval architecture (no retained user data, in-account cross-family LLM judge); (c) clean-vs-degraded paired analysis isolating document-quality loss from model error; (d) empirical results + failure taxonomy. Backbone sources already gathered in AI_EVALUATION_RESEARCH.md §7. Candidate venues: BEA or similar NLP-for-education workshop first, then ACL Findings / AIES / JAIED.

**Cross-cutting assets:** DIS 2025 co-design paper (doi:10.1145/3715336.3735778) as prior work lineage; the blog RFC + critique summary as participatory-methods evidence.

**Process notes:** Northeastern IRB consultation needed before any practitioner/parent study data is used in a publication (practitioner realism review likely counts as human-subjects research). Decide dataset license + hosting at publication time. No AI attribution in authorship; team authorship per Burnes norms.

## 2. Chronological log

### 2026-07 (session 1): scoping, pipeline audit, format research, design

- **Read/audited** AI_EVALUATION_RESEARCH.md end to end. Baseline finding it establishes: the production pipeline's only automated quality gate is a Pydantic shape check (9 sections); no faithfulness, extraction-accuracy, translation, readability, or feedback measurement exists; no LLM I/O is persisted (FERPA-by-design), so evaluation requires deliberately built golden data.
- **Verified the codebase contract** a golden dataset must mirror (file:line refs in §5):
  - OCR: pipeline consumes only `pages[].index` (0-based) + `pages[].markdown` from raw Mistral OCR JSON; agent tools display pages 1-based, so ground-truth `page_numbers` are 1-based. No page limits or chunking anywhere.
  - Redaction: AWS Comprehend, allowlist keeps NAME + DATE_TIME verbatim; every other PII type replaced with `[{TYPE}]` tokens in place. Redacted JSON is shape-identical to raw. Stats computed but only logged.
  - Parsing: exactly 9 enforced section titles (Present Levels, Eligibility, Placement, Goals, Services, Informed Consent, Accommodations, Key People, Strengths); `SECTION_KEY_POINTS` is a ready-made annotation guide; missing sections silently backfilled with placeholder text and `page_numbers:[1]`; services target format "300 min/week (5 hrs/week)".
  - Meeting notes: verbatim extraction from redacted text; empty string when absent. Product fact: extracted but never displayed to parents (deprioritize in evals).
  - Translation: 4 glossaries (~298 en→{es,vi,zh,ar} pairs each); section titles stay English; Arabic keeps Latin acronyms + Western digits.
  - Environment: repo `.env` has only MISTRAL_API_KEY (OpenAI key lives in SSM `/ai-iep/OPENAI_API_KEY`); local Python 3.14 incompatible with pinned pydantic 2.10.6, so evals venv must be Python 3.12; step directories collide on module names, so local runs need subprocess-per-stage `sys.path` isolation.
- **Format research (web):** no single IEP format exists. Federal law fixes content; states/districts choose forms. Documented variation: length 3p (MT) to 28p (WA secondary); transition age 16 default, 14 in NY/KY/IA, 9th-grade entry TX/GA, start of high school CA (2025); goal structure domain-based (CT/RI/KS) vs goal-area (TX); eligibility embedded (IN/LA) vs separate; governance mandated-single-form (NY) vs SELPA-shared (CA SEIS) vs optional model forms (WA and most). District software (SEIS, EasyIEP/PCG, Frontline, PowerSchool Special Programs, Embrace) largely determines layout; PCG claims ~1 in 5 US IEPs.
- **Population statistics** for scenario weighting: ~7.9M students served under IDEA (2023-24, NCES); disability shares approx: SLD ~32%, speech/language ~19%, OHI ~15%, autism ~13-14%, DD ~7%, ID ~6%, ED ~5%, multiple ~2%, low-incidence ≤1% each. (Old team blog said 7.5M; public writing uses "nearly 8 million".)
- **Primary-document deep dive:** WA OSPI redacted sample E, page by page (15p, grade 9, EBD, annual review). Key structural findings now baked into the design: real uploads are *packets* (invitation letter, contact-attempt log, cover page, special-factors checklist, PLEP narratives with quantified baselines, transition, per-goal blocks, accommodations table, assessment participation grid, services matrix with totals lines, LRE options grid, PWN); frequency conventions differ from the parser's target format ("40 Minutes / 1 Times Daily" vs "N min/week"), motivating surface+normalized dual annotation; LRE grids list *considered-and-rejected* placements (natural must-not-contain traps); observed quirks: blank continuation pages, goal blocks split mid-sentence at page breaks, skewed scans, identical 5-line ID header on every page.
- **Design decisions:** see §4 (D1-D10).
- **Implementation plan** written (plan file, session artifact): generator architecture (blueprint → LLM narrative → HTML/PDF → real OCR → redaction → annotation → gates), 8 template profiles with quotas, validation gates, review tooling, smoke runs, cost/effort estimates (~$25-40 total API cost, 11-13 eng days + ~8.5h review).

### 2026-07 (session 3): team research merge + nearest-neighbor paper

- **Nearest published neighbor found (user tip): Chen & Ou 2026** [S22], "Automated IEP Generation from Traditional Chinese Parent-Teacher Interviews via Corpus-Grounded Feature Diffusion" (arXiv 2606.09603). Synthetic IEP-adjacent data for *training* a local Breeze-7B (teacher-facing writing, Taiwan preschool), vs our *evaluation* data for a parent-facing reading tool. ## 7. Threats to validity / limitations (track as they arise)

1. Synthetic-real gap: no de-identified real IEPs *in the committed corpus*; public redacted samples used only as local structural controls (black-bar redactions make them unfit for name-extraction testing). Partially mitigated July 2026: the team holds 4-5 real IEPs usable for local metric calibration (provenance/consent to confirm), and SPEDucational offers practitioner-informed synthetic content.
2. Generator and system-under-test share a model family (GPT-4.1) unless the cross-family slice runs; mitigated by D2/D3 (truth never comes from the generator model) and stamped provenance.
3. Judge contamination (Claude judges; if Claude ever generates narrative, keep human-reviewed annotations + real-doc track), per AI_EVALUATION_RESEARCH §5.3.
4. Degradation realism: scan-simulation parameters are assumptions until practitioner review confirms they resemble real parent uploads.
5. Practitioner realism review not yet conducted (recruiting is an open item with lead time); until then realism rests on template fidelity + structural comparison.
6. English-source-only corpus mirrors the pipeline's assumption; non-English-source uploads (e.g., district-issued Spanish IEPs) are unrepresented.
7. Single-system results (P2): the framework generalizes, the numbers describe one pipeline.
8. US-centric; findings may not transfer to other special-education documentation regimes.
